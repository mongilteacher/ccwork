## TF-1 — 사이드바에 태그 목록 표시

### 설명

태그 필터링의 **워킹 스켈레톤**. 아직 클릭해도 아무 일이 일어나지 않지만, 전체 노트의 태그가 사이드바 상단에 카운트와 함께 모여 보이는 데까지 관통시킨다.

이 슬라이스의 무게중심은 **집계 규칙**이다. 대소문자 병합·정렬·표기 선택이 모두 여기서 결정되고, 이후 슬라이스는 그 결과를 소비하기만 한다.

- `src/domain/tagFilter.ts` 신규 — `countTags(notes)` 순수 함수. `TagCount { tag, count }` 타입 정의
- 집계 규칙: `normalizeTag` 후 **소문자 비교로 병합**, 표기는 **먼저 등장한 것** (PRD ADR-4)
- 정렬: **카운트 내림차순**, 동점이면 표기 기준 `localeCompare`
- `src/components/TagFilterBar.tsx` 신규 — `{ tagCounts }`만 받는 순수 컴포넌트. 칩은 `button` 요소 (spec §4.6)
- `Layout`의 사이드바 slot을 `sidebar` 하나에서 태그 영역 + 노트 목록 2단으로 배치. **레이아웃 단 수(2단)는 그대로**
- 태그가 0개면 영역 전체(제목·구분선 포함)를 렌더하지 않는다

### 완료조건 (Acceptance Criteria)

- [ ] Given 노트들에 태그가 저장돼 있을 때, When 앱을 열면, Then 사이드바 상단에 모든 태그가 칩으로 표시된다
- [ ] Given 태그 `#회의`를 가진 노트가 3개일 때, When 태그 목록을 보면, Then 칩에 카운트 `3`이 함께 표시된다
- [ ] Given 카운트가 3·1·2인 태그가 있을 때, When 태그 목록을 보면, Then 3 → 2 → 1 순으로 정렬돼 있다
- [ ] Given 카운트가 같은 태그가 둘 있을 때, When 태그 목록을 보면, Then 가나다순으로 정렬돼 있다
- [ ] Given 노트 A에 `React`, 노트 B에 `react`가 있을 때, When 태그 목록을 보면, Then 칩은 하나이고 카운트는 `2`이며 표기는 먼저 등장한 쪽이다
- [ ] Given 어떤 노트에도 태그가 없을 때, When 앱을 열면, Then 태그 영역(제목·구분선 포함)이 렌더되지 않는다
- [ ] Given 노트 목록이 로딩 중이거나 에러일 때, When 사이드바를 보면, Then 태그 영역이 렌더되지 않는다
- [ ] 태그 칩이 `button` 요소이며 키보드로 포커스된다
- [ ] 노트 목록과 "노트 N개" 표시는 이전과 동일하게 동작한다

### 시나리오

**Given** `["회의","팀"]`, `["회의"]`, `["책"]` 태그를 가진 노트 3개가 있고
**When** 사용자가 앱을 열면
**Then** 사이드바 상단에 `회의 2`, `책 1`, `팀 1` 칩이 이 순서로 표시된다

**Given** 노트 A에 `React`, 노트 B에 `react`가 저장돼 있고
**When** 사용자가 태그 목록을 보면
**Then** `React 2` 칩 하나만 표시된다 (A가 먼저 등장한 경우)

**Given** 모든 노트의 `tags`가 빈 배열이고
**When** 사용자가 앱을 열면
**Then** 사이드바에는 노트 목록만 있고 태그 영역은 흔적도 없다

## TF-2 — 태그를 클릭하면 노트가 강조됨

### 설명

이 기능의 **핵심 가치**. 태그를 클릭하면 그 태그를 가진 노트 카드가 강조되고, 다른 태그를 클릭하면 강조가 옮겨간다.

강조는 **숨김이 아니다** — 비대상 노트도 목록에 그대로 있고 순서도 안 바뀐다 (PRD ADR-2). "노트 N개"도 전체 개수를 유지한다.

- `src/domain/tagFilter.ts`에 `isHighlighted(note, selectedTag)` 추가 — 대소문자 무시 비교(TF-1의 집계 기준과 동일)
- `App.tsx`에 `selectedTag: string | null` 로컬 state + `handleSelectTag` (PRD ADR-1)
- `TagFilterBar`에 `selectedTag` · `onSelectTag` props 추가. 선택된 칩은 시각적으로 구분된다
- `NoteList` → `NoteItem`으로 `isHighlighted` prop 전달
- **`isSelected`(편집 중인 노트) 강조와 시각적으로 구분**되어야 한다. 둘이 동시에 켜질 수 있다 (PRD §3)
- 강조 표현은 `design-system` 스킬로 정본 확인 후 결정. 테두리로 구분하지 않는다(No-Line Rule)

### 완료조건 (Acceptance Criteria)

- [ ] Given 태그 `#회의`를 가진 노트가 2개일 때, When 사용자가 `#회의` 칩을 클릭하면, Then 그 2개가 강조된다
- [ ] Given `#회의`를 클릭한 상태에서, When 목록을 보면, Then `#회의`가 없는 노트도 **목록에 그대로 남아 있다**
- [ ] Given `#회의`를 클릭한 상태에서, When 목록을 보면, Then 노트 순서가 클릭 전과 동일하다
- [ ] Given `#회의`를 클릭한 상태에서, When 목록 상단을 보면, Then "노트 N개"가 **전체 개수** 그대로다
- [ ] Given `#회의`가 선택된 상태에서, When 사용자가 `#책` 칩을 클릭하면, Then `#회의` 선택이 풀리고 `#책` 노트만 강조된다
- [ ] Given 아무 태그도 선택하지 않았을 때, When 목록을 보면, Then 어떤 노트도 강조되지 않는다
- [ ] Given 태그가 선택된 상태에서, When 태그 목록을 보면, Then 선택된 칩이 나머지 칩과 시각적으로 구분된다
- [ ] Given 노트 A가 편집 중(`isSelected`)이면서 강조 대상일 때, When 카드를 보면, Then 두 상태가 서로 구분된다
- [ ] Given 노트 A에 `React`, 노트 B에 `react`가 있을 때, When 그 칩을 클릭하면, Then **두 노트 모두** 강조된다

### 시나리오

**Given** `#회의` 노트 2개와 `#책` 노트 1개가 있고
**When** 사용자가 `회의 2` 칩을 클릭하면
**Then** `#회의` 노트 2개가 강조되고, `#책` 노트는 강조 없이 목록에 남는다

**Given** `#회의`가 선택돼 있고
**When** 사용자가 `책 1` 칩을 클릭하면
**Then** `#회의` 노트의 강조가 사라지고 `#책` 노트가 강조된다

**Given** 노트 A는 `React`, 노트 B는 `react` 태그를 갖고 있고
**When** 사용자가 그 칩을 클릭하면
**Then** A와 B가 **둘 다** 강조된다

## TF-3 — 필터에서 빠져나오는 모든 경로

### 설명

필터를 켜는 것만큼 **끄는 것**이 분명해야 한다. 이 슬라이스는 선택이 풀리는 두 경로를 완성한다.

1. **사용자가 직접** — 선택된 칩을 다시 클릭
2. **저절로** — 선택한 태그가 세상에서 사라졌을 때(마지막 노트에서 태그 제거, 또는 그 노트 삭제)

2번은 `useEffect`로 state를 고치지 않고 **파생값으로** 처리한다 (PRD ADR-3). "태그 목록에 없는 선택 태그는 선택되지 않은 것으로 본다"를 렌더 시점에 계산하면, 태그가 사라지는 모든 경로가 코드 한 줄 없이 처리된다.

- `TagFilterBar`(또는 `App`)에서 같은 칩 재클릭 시 `null`로 토글
- 강조 판정을 **태그 목록 기준**으로 통과시켜, 목록에 없는 선택 태그는 무시되게 한다
- `selectedTag` state에 사라진 태그 문자열이 남을 수 있다는 점을 함수 주석에 남긴다 (ADR-3 Consequences)
- E2E: `e2e/tag-filter.spec.ts` — 실제 브라우저 + json-server 왕복이 필요한 여정만 (`e2e-write` 스킬)

### 완료조건 (Acceptance Criteria)

- [ ] Given `#회의`가 선택된 상태에서, When 사용자가 `#회의` 칩을 다시 클릭하면, Then 선택이 해제되고 아무 노트도 강조되지 않는다
- [ ] Given `#책`을 가진 노트가 1개뿐이고 그 태그가 선택된 상태에서, When 사용자가 그 노트에서 `#책` 태그를 지우고 저장하면, Then 칩이 사라지고 강조도 사라진다
- [ ] Given `#책` 태그가 선택된 상태에서, When 사용자가 `#책`을 가진 마지막 노트를 삭제하면, Then 칩이 사라지고 강조도 사라진다
- [ ] Given `#회의` 노트가 3개이고 선택된 상태에서, When 그중 1개에서 태그를 지우고 저장하면, Then 칩은 `회의 2`로 줄고 선택은 유지되며 남은 2개가 강조된다
- [ ] Given 태그가 선택된 상태에서, When 사용자가 새로고침하면, Then 선택이 해제된 전체 보기로 시작한다
- [ ] 선택 해제 처리에 `useEffect` + `setSelectedTag`를 쓰지 않는다 (ADR-3)
- [ ] E2E가 태그 선택 → 태그 제거 저장 → 강조·칩 소멸 여정을 실제 서버 왕복으로 검증한다

### 시나리오

**Given** `#회의`가 선택돼 노트 2개가 강조돼 있고
**When** 사용자가 `회의 2` 칩을 다시 클릭하면
**Then** 강조가 모두 사라지고 칩도 선택 해제 표시로 돌아간다

**Given** `#책` 태그를 가진 노트가 딱 1개이고 그 태그가 선택돼 있고
**When** 사용자가 그 노트를 열어 `#책` 칩을 지우고 저장하면
**Then** 사이드바에서 `책` 칩이 사라지고, 강조된 노트도 없어진다

**Given** `#회의` 태그를 가진 노트가 3개이고 선택돼 있고
**When** 사용자가 그중 하나에서 태그를 지우고 저장하면
**Then** 칩은 `회의 2`로 바뀌고 선택은 그대로이며 남은 2개만 강조된다
