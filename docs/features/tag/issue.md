# 태그 기능 이슈 분해

> 기반: [`prd.md`](./prd.md) · [`spec-fixed.md`](./spec-fixed.md)
> 원칙: **수직 슬라이싱** — 각 이슈는 타입→데이터→도메인→훅→컴포넌트를 관통해 **그 자체로 데모 가능한 사용자 가치**를 낸다. 계층별(수평)로 자르지 않는다.

## 슬라이스 개요

| #     | 제목                      | 관통 계층                      | 관련 US     | 선행  |
| ----- | ------------------------- | ------------------------------ | ----------- | ----- |
| TAG-1 | 저장된 태그를 칩으로 표시 | type · db.json · component     | US-3        | —     |

각 이슈의 완료조건은 항상 `npm run typecheck`·`npm run lint` 통과를 전제로 한다(중복 기재 생략).

## TAG-1 — 저장된 태그를 칩으로 표시

### 설명

태그 기능의 **워킹 스켈레톤**. 데이터 구조(`Note.tags`)를 도입하고, 노트를 열었을 때 저장된 태그가 칩(pill)으로 보이는 데까지 최소 경로를 관통시킨다. 이 슬라이스는 **읽기 전용** — 추가·삭제·검증은 없다. 입력 필드도 아직 없다.

- `Note` 타입에 `tags: string[]` **필수 필드** 추가, `src/types/note.ts:7`의 미완성 주석 제거 (PRD ADR-1)
- `db.json` 기존 노트 3건에 `"tags"` 추가 — **표시 검증을 위해 최소 1건은 실제 태그 값**을 넣는다(예: `["React", "공부"]`), 나머지는 `[]`
- `TagInput` 컴포넌트 신규 — 이번엔 **칩 목록 렌더만** 담당(`{ tags }` 소비). Context 미소비, 순수 컴포넌트
- `NoteEditor`에 `tags` 로컬 state + 폼 동기화 `useEffect`에 `setTags` 추가, `<TagInput>` 렌더
- `createNote` 시그니처에 `tags` 파라미터 추가 (기존 호출부는 `[]` 전달 — 생성 UI는 TAG-2에서)

### 완료조건 (Acceptance Criteria)

- [ ] `Note` 타입에 `tags: string[]`가 있고 optional이 아니다
- [ ] `db.json` 기존 노트 3건이 모두 `tags` 필드를 가지며, 최소 1건은 비어있지 않다
- [ ] 태그가 있는 노트를 선택하면 각 태그가 칩으로 렌더된다
- [ ] 태그가 0개인 노트는 칩 영역이 비고 "태그 없음" 류 문구는 없다
- [ ] 칩 스타일이 시맨틱 토큰만 사용한다(원시 Tailwind 색상·테두리 금지 — design-system 훅 통과)
- [ ] 다른 노트를 선택하면 칩 목록이 그 노트의 태그로 바뀐다

### 시나리오

**Given** `tags: ["React", "공부"]`로 저장된 노트가 있고
**When** 사용자가 목록에서 그 노트를 선택하면
**Then** 편집 화면에 `React`·`공부` 칩 2개가 표시된다

**Given** `tags: []`인 노트가 있고
**When** 사용자가 그 노트를 선택하면
**Then** 칩 영역은 비어 있고 빈 상태 안내 문구는 나타나지 않는다

**Given** 태그가 있는 노트 A를 보고 있고
**When** 사용자가 태그가 다른 노트 B를 선택하면
**Then** 칩 목록이 B의 태그로 즉시 교체된다

## TAG-2 — Enter로 태그 추가 후 저장

### 설명

쓰기 왕복을 완성하는 슬라이스. 입력 필드에서 `Enter`로 태그를 확정해 칩으로 추가하고, **저장 버튼**을 눌러 `title`·`content`와 함께 서버에 한 번에 반영한다(PRD ADR-2). 이 슬라이스의 검증은 **빈 값 무시 + 앞뒤 공백 `trim`** 수준까지만 — 중복·길이·개수 검증은 TAG-4, 정규화 파이프라인 전체와 IME는 TAG-5에서 견고화한다.

- `src/domain/tag.ts` 신규 — `addTag(tags, raw)` 도입. 이번 단계는 `trim` + 빈 값 무시 + 배열 끝 추가까지(PRD ADR-3의 시그니처 골격)
- `src/hooks/useTagInput.ts` 신규 — 입력 문자열 state, `Enter` 핸들러, 확정 시 `onChange`로 상위에 배열 전달, 입력 비우고 포커스 유지
- `TagInput`에 입력 필드 추가, `useTagInput` 연결
- `NoteEditor.handleSave`에서 `createNote(title, content, tags)` / `updateNote(id, { title, content, tags })`로 `tags` 전달
- `NotesContext.createNote`에 `tags` 파라미터 전달(ADR-2 — mutation 추가 없음)
- 첫 도메인 단위 테스트 파일 `src/domain/tag.test.ts` 생성(기본 add/trim/빈 값 케이스)

### 완료조건 (Acceptance Criteria)

- [ ] 입력 후 `Enter`를 누르면 칩이 추가되고 입력 필드가 비워진다
- [ ] 태그 추가 후 입력 필드의 포커스가 유지되어 연속 입력이 가능하다
- [ ] 빈 문자열/공백만 입력하고 `Enter`를 눌러도 추가되지 않는다
- [ ] 앞뒤 공백이 있는 값은 `trim`되어 추가된다
- [ ] 칩 추가는 서버를 호출하지 않고 로컬 state만 바꾼다
- [ ] 저장 버튼을 누르면 `tags`가 본문과 함께 1회 요청으로 전송된다
- [ ] 저장 후 새로고침해도 태그가 유지된다
- [ ] 새 노트를 태그와 함께 생성할 수 있다
- [ ] 저장에 실패해도 태그 로컬 state가 유지된다(재시도 가능)
- [ ] `src/domain/tag.ts`에 대한 단위 테스트가 존재하고 통과한다

### 시나리오

**Given** 편집 화면에서 입력 필드에 `TypeScript`를 입력했고
**When** 사용자가 `Enter`를 누르면
**Then** `TypeScript` 칩이 추가되고 입력 필드가 비워지며 포커스가 유지된다

**Given** 입력 필드가 비어 있거나 공백만 있고
**When** 사용자가 `Enter`를 누르면
**Then** 아무 칩도 추가되지 않는다

**Given** 태그를 추가해 로컬 state에만 있는 상태이고
**When** 사용자가 저장 버튼을 누르면
**Then** `tags`가 `title`·`content`와 함께 한 번의 요청으로 서버에 저장된다

**Given** 태그를 추가하고 저장한 뒤
**When** 사용자가 페이지를 새로고침하고 그 노트를 다시 열면
**Then** 추가했던 태그가 그대로 보인다

**Given** 새 노트를 작성하며 태그를 입력했고
**When** 사용자가 저장 버튼을 누르면
**Then** 태그를 포함한 노트가 생성된다

**Given** 태그를 추가한 상태에서 저장이 실패했고
**When** 요청이 에러로 끝나면
**Then** 입력했던 태그가 화면에서 사라지지 않고 다시 저장을 시도할 수 있다

## TAG-3 — 칩 × 로 태그 삭제

### 설명

각 칩에 삭제용 `×` 버튼을 붙여, 클릭 즉시 로컬 `tags`에서 제거한다. 확인 다이얼로그는 없다. 삭제 역시 로컬 state만 바꾸므로 취소 버튼이 그대로 되돌린다(ADR-2).

- `TagInput` 칩에 `×` 버튼 추가, 클릭 시 해당 태그를 뺀 배열을 `onChange`로 전달
- 카드 내 버튼 이벤트 규약(`e.stopPropagation()`)을 따른다

### 완료조건 (Acceptance Criteria)

- [ ] 각 칩에 삭제용 `×` 버튼이 있다
- [ ] `×`를 클릭하면 확인 다이얼로그 없이 즉시 해당 태그가 제거된다
- [ ] 삭제는 로컬 state만 바꾸고 서버를 호출하지 않는다
- [ ] 삭제 후 저장하면 삭제 결과가 서버에 반영된다
- [ ] 저장 전 취소를 누르면 삭제가 되돌아간다
- [ ] 같은 이름 태그가 없으므로(중복 불가) 정확히 클릭한 칩만 사라진다

### 시나리오

**Given** `React`·`공부` 칩 2개가 있고
**When** 사용자가 `공부` 칩의 `×`를 클릭하면
**Then** `공부` 칩만 즉시 사라지고 `React`는 남는다

**Given** 칩을 삭제해 로컬 state가 바뀐 상태이고
**When** 사용자가 취소 버튼을 누르면
**Then** 삭제했던 태그가 원래대로 복원된다(서버 미전송)

**Given** 칩을 삭제한 뒤
**When** 사용자가 저장 버튼을 누르고 새로고침하면
**Then** 삭제된 태그는 다시 나타나지 않는다

## TAG-4 — 입력 검증과 인라인 안내

### 설명

추가 시점의 검증을 도입한다. **우선순위 순서로 첫 번째로 걸린 규칙만** 적용하고(중복 → 길이 → 개수 순은 spec-fixed §5.3 기준), 실패 사유를 **입력 필드 바로 아래 인라인 한 줄**로 보여준다(ADR-4). 이 프로젝트에 폼 검증 피드백을 처음 도입하는 슬라이스다.

- `src/domain/tag.ts`에 `validateTag(value, tags): TagError | null`와 `TagError`(`'duplicate' | 'tooLong' | 'tooMany'`), 상수 `MAX_TAG_LENGTH = 20`·`MAX_TAG_COUNT = 10` 추가
- 중복은 **대소문자 무시**, 저장값은 **먼저 입력된 원문 유지**
- 길이는 `[...value].length`(코드 포인트) 기준
- `useTagInput`에 에러 코드 state 추가, `onChange` 시 에러 소멸(타이머 금지)
- UI 계층에서 `TagError` → 한국어 문구 매핑(도메인은 코드만 반환)
- 태그가 10개면 입력 필드 `disabled` + placeholder 교체
- `src/domain/tag.test.ts`에 검증 규칙 `it.each` 테이블 추가

### 완료조건 (Acceptance Criteria)

- [ ] 이미 있는 태그를 추가하면 거부되고 `이미 추가된 태그입니다`가 뜬다
- [ ] 중복 판정은 대소문자를 무시한다(`React` 존재 시 `react`도 중복)
- [ ] 21자 이상 태그는 거부되고 `태그는 20자까지 입력할 수 있습니다`가 뜬다
- [ ] 길이 계산이 `[...value].length` 기준이라 이모지 포함 태그가 부당하게 거부되지 않는다
- [ ] 태그가 10개면 추가가 막히고 입력 필드가 `disabled`되며 placeholder가 안내 문구로 바뀐다
- [ ] 10개에서 하나 삭제하면 입력 필드가 다시 활성화된다
- [ ] 여러 규칙을 동시에 위반해도 우선순위상 첫 규칙의 메시지 하나만 보인다
- [ ] 안내 메시지는 사용자가 입력값을 바꾸는 순간 사라진다(타이머 자동 제거 아님)
- [ ] `alert()`·`confirm()`을 쓰지 않는다
- [ ] 검증 규칙에 대한 `it.each` 단위 테스트가 통과한다

### 시나리오

**Given** `React` 칩이 이미 있고
**When** 사용자가 `react`를 입력하고 `Enter`를 누르면
**Then** 추가되지 않고 입력 필드 아래에 `이미 추가된 태그입니다`가 표시된다

**Given** 21자 태그를 입력했고
**When** 사용자가 `Enter`를 누르면
**Then** 추가되지 않고 `태그는 20자까지 입력할 수 있습니다`가 표시된다

**Given** 태그가 이미 10개 있고
**When** 사용자가 태그를 더 추가하려 하면
**Then** 입력 필드가 `disabled`이고 placeholder가 `태그는 최대 10개입니다`로 바뀌어 추가할 수 없다

**Given** 안내 메시지가 표시된 상태이고
**When** 사용자가 입력 필드의 값을 수정하면
**Then** 안내 메시지가 즉시 사라진다

**Given** 태그가 10개라 입력이 막힌 상태이고
**When** 사용자가 칩 하나를 삭제하면
**Then** 입력 필드가 다시 활성화된다

## TAG-5 — 정규화·한글 IME 견고화

### 설명

붙여넣기·한글 입력에서 발생하는 엣지케이스를 막는 마지막 슬라이스. 정규화 파이프라인 전체(개행·탭→공백, 연속 공백 축약, `trim`, NFC)를 확정하고, 한글 IME 조합 확정 `Enter`가 태그를 이중 추가하지 않도록 가드한다(spec-fixed §5.2·§6.1). 검증·저장은 항상 정규화된 값을 기준으로 한다.

- `src/domain/tag.ts`의 `normalizeTag(raw)` 파이프라인 확정 — 순서 고정: 개행·탭 치환 → 연속 공백 축약 → `trim` → `normalize('NFC')`
- `addTag`/`validateTag`가 정규화된 값을 기준으로 동작하도록 정리
- `useTagInput`의 `Enter` 핸들러에 `e.nativeEvent.isComposing` 가드
- 중복 판정이 NFC 정규화 후 이뤄져 눈에 같은 한글이 중복으로 걸러진다
- `src/domain/tag.test.ts`에 정규화·엣지케이스 `it.each` 테이블 추가(spec-fixed §6.2)

### 완료조건 (Acceptance Criteria)

- [ ] 한글을 조합 중 누른 `Enter`로는 태그가 추가되지 않고, 조합 확정 후의 `Enter`로만 추가된다
- [ ] 한글 태그가 이중으로 추가되지 않는다
- [ ] 여러 줄 텍스트를 붙여넣으면 개행이 공백으로 치환돼 한 줄 태그가 된다
- [ ] `React  Query`(연속 공백)가 `React Query`로 정규화되어 추가된다
- [ ] macOS에서 복사한 NFD 한글이 NFC로 정규화돼 기존 태그와 중복 판정된다
- [ ] `React, Vue`는 쉼표로 분리되지 않고 하나의 태그로 저장된다
- [ ] 정규화·엣지케이스에 대한 `it.each` 단위 테스트가 통과한다

### 시나리오

**Given** 한글 입력기로 `태그`를 조합하고 있고
**When** 조합을 확정하는 `Enter`가 발생하면
**Then** 그 `Enter`로는 태그가 추가되지 않는다(다음 `Enter`에서만 추가)

**Given** 여러 줄로 된 텍스트를 클립보드에 담았고
**When** 사용자가 입력 필드에 붙여넣고 `Enter`를 누르면
**Then** 개행이 공백으로 바뀐 한 줄짜리 태그 하나가 추가된다

**Given** `한글`(NFC)이 이미 태그로 있고
**When** 사용자가 macOS에서 복사한 `한글`(NFD)을 입력하고 `Enter`를 누르면
**Then** 정규화 후 같은 값으로 판정되어 중복으로 거부된다

**Given** 입력 필드에 `React, Vue`를 입력했고
**When** 사용자가 `Enter`를 누르면
**Then** 쉼표로 분리되지 않고 `React, Vue` 한 개의 태그로 추가된다

## 이번 분해에서 제외 (PRD §4 Out of Scope)

아래는 **태그 기능이지만 이번 이슈 세트에 포함하지 않는다.** 필요해지면 별도 이슈로 연다.

- 태그로 노트 필터링·검색, 사이드바 태그 클라우드, 태그별 개수 (PRD 4.1)
- 자동완성, 쉼표 자동 분리, `Backspace` 마지막 칩 삭제, 드래그 정렬 (PRD 4.2)
- 태그 rename·merge·정리, 태그 관리 화면 (PRD 4.3)
- 태그 색상·아이콘·계층·설명 (PRD 4.4)
- 노트 목록 카드(`NoteItem`)에 태그 표시 (PRD 4.5)
- 칩 키보드 내비게이션, 스크린리더 라이브 리전 (PRD 4.7)
