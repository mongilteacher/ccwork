# 태그 기능 명세서 (구현용)

`spec-orginal.md`의 기능 정의서를 구현 가능한 수준으로 구체화한 문서다.
원본은 "무엇을"만 정의돼 있어 데이터 구조·UI 패턴·엣지케이스를 확정했다.

> **결정 표기**
> ✅ = 논의로 확정된 항목 / 🔸 = 추천안대로 임의 결정한 항목

---

## 1. 기능 개요

노트에 태그를 추가·삭제하고, 노트 상세(편집) 화면에서 태그 목록을 확인한다.

## 2. 데이터 구조

### ✅ Note 문서에 배열로 저장

별도 컬렉션이나 조인 테이블을 두지 않는다. json-server 목 API에서 조회가 한 번으로 끝나고, 기존 3계층 흐름(`api` → `Context` → `UI`)을 그대로 확장할 수 있다.

```ts
// src/types/note.ts
export interface Note {
  id: string;
  title: string;
  content: string;
  tags: string[]; // ← 추가 (필수)
  createdAt: string;
  updatedAt: string;
}
```

```jsonc
// db.json
{
  "id": "1",
  "title": "첫 번째 노트",
  "content": "eeeee",
  "tags": ["React", "공부"],
  "createdAt": "2024-01-01T00:00:00.000Z",
  "updatedAt": "2026-03-23T13:57:08.282Z",
}
```

### ✅ 기존 데이터는 db.json을 직접 수정

`db.json`의 기존 노트 3개에 `"tags": []`를 직접 추가한다. 타입은 **optional이 아닌 필수**(`tags: string[]`)로 둔다.

- 목 데이터는 우리가 소유하므로 마이그레이션 코드가 필요 없다.
- 필수 타입이라 `createNote`에서 `tags` 누락을 컴파일러가 잡는다.
- 사용처에 `?? []` 방어 코드가 퍼지지 않는다.

🔸 `api` 계층에서 `tags`를 정규화하지 **않는다**. `src/api/notes.ts`는 순수 fetch 래퍼라는 기존 규약을 깨지 않기 위함이다.

### 🔸 태그 값 형식

| 항목     | 규칙                                                |
| -------- | --------------------------------------------------- |
| 타입     | `string`                                            |
| 정규화   | 개행·탭 치환 → 연속 공백 축약 → `trim` → NFC (§5.2) |
| 대소문자 | 입력한 원문 그대로 저장 (중복 판정에서만 무시)      |
| 길이     | 최대 20자 (`[...value].length` 기준)                |
| 개수     | 노트당 최대 10개                                    |
| 순서     | 추가한 순서 유지 (정렬하지 않음)                    |

## 3. UI 명세

### ✅ Enter로 확정하는 칩(pill) 방식

`NoteEditor`의 내용 입력 아래, 버튼 영역 위에 태그 섹션을 둔다.

```
┌─ 노트 편집 ────────────────────┐
│ 제목                            │
│ ─────────────────────────── │
│ 내용을 입력하세요...              │
│                                 │
│ ─────────────────────────── │
│ 태그                            │
│ ⌈React ×⌋ ⌈공부 ×⌋              │
│ ┌───────────────────────┐   │
│ │ 태그 입력 후 Enter        │   │
│ └───────────────────────┘   │
│ ─────────────────────────── │
│ [저장]  [취소]                  │
└─────────────────────────────────┘
```

- **추가**: 입력 후 `Enter` → 칩으로 추가되고 입력 필드는 비워진다.
- **삭제**: 칩의 `×` 클릭 → 즉시 목록에서 제거 (확인 다이얼로그 없음).
- **섹션 라벨**: 기존 편집기와 동일하게 `text-xs font-semibold tracking-widest uppercase text-muted-foreground`.
- **칩 스타일**: 시맨틱 토큰 사용 (`bg-muted`, `text-foreground`, `rounded-xl`). 원시 Tailwind 색상 금지.

### 🔸 태그가 하나도 없을 때

칩 영역을 비워두고 입력 필드만 노출한다. "태그가 없습니다" 같은 빈 상태 문구는 두지 않는다 — 바로 아래 입력 필드가 무엇을 해야 하는지 이미 설명하기 때문이다.

### 🔸 노트 목록(`NoteItem`)에는 태그를 표시하지 않는다

원본 정의서가 "노트 상세 화면에서 확인"만 요구했다. 목록 카드는 이미 제목·내용·날짜로 밀도가 높아 이번 범위에서 제외한다.

## 4. 상호작용 규칙

### 🔸 저장 시점 — 저장 버튼을 누를 때 함께 반영

칩 추가·삭제는 **로컬 state만** 변경하고, 서버에는 저장 버튼을 눌렀을 때 `title`·`content`와 함께 한 번에 보낸다.

```ts
// 칩 추가 — 서버 호출 없음
setTags((prev) => [...prev, newTag]);

// 저장 버튼 — 한 번에
await updateNote(selectedNoteId, { title, content, tags });
await createNote(title, content, tags);
```

즉시 반영 방식을 택하지 않은 이유:

- **취소 버튼의 의미가 깨진다.** 태그만 이미 저장돼 있으면 "취소"가 일부만 되돌린다.
- **새 노트 생성 중에는 불가능하다.** `isCreating` 상태에서는 노트 `id`가 없어 PATCH할 대상이 없다.
- 기존 편집기 규약(저장 버튼으로 확정)과 일관된다.

### 🔸 폼 동기화

`NoteEditor`의 기존 `useEffect`에서 `tags`도 함께 초기화한다. 의존성 배열 `[selectedNoteId, isCreating]`과 `eslint-disable-line`은 **그대로 유지**한다 (의도적 설계).

```ts
useEffect(() => {
  if (selectedNote) {
    setTitle(selectedNote.title);
    setContent(selectedNote.content);
    setTags(selectedNote.tags); // ← 추가
  } else if (isCreating) {
    setTitle('');
    setContent('');
    setTags([]); // ← 추가
  }
}, [selectedNoteId, isCreating]); // eslint-disable-line react-hooks/exhaustive-deps
```

## 5. 유효성 검증

### 5.1 상수

```ts
const MAX_TAG_LENGTH = 20; // 태그 1개의 최대 글자 수
const MAX_TAG_COUNT = 10; // 노트 1개의 최대 태그 수
```

### 5.2 정규화 파이프라인 (순서 고정)

검증과 저장은 **항상 정규화된 값**을 기준으로 한다. 순서가 바뀌면 결과가 달라지므로 아래 순서를 지킨다.

```ts
function normalizeTag(raw: string): string {
  return raw
    .replace(/[\r\n\t]+/g, ' ') // 1. 개행·탭 → 공백 (붙여넣기 대응)
    .replace(/\s{2,}/g, ' ') // 2. 연속 공백 → 1개
    .trim() // 3. 앞뒤 공백 제거
    .normalize('NFC'); // 4. 유니코드 정규화
}
```

| 단계                  | 이유                                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 1. 개행·탭 치환       | 여러 줄 텍스트를 붙여넣어도 태그 하나로 처리                                                                              |
| 2. 연속 공백 축약     | `React  Query`와 `React Query`를 같은 태그로                                                                              |
| 3. `trim`             | 앞뒤 공백만 다른 중복 방지                                                                                                |
| 4. `normalize('NFC')` | macOS에서 복사한 한글은 자모가 분리된 NFD로 들어온다. 정규화하지 않으면 눈에 똑같은 `한글`이 **중복으로 걸러지지 않는다** |

### 5.3 검증 규칙 — 위에서부터 먼저 걸리는 것 하나만 적용

여러 규칙을 동시에 위반해도 **첫 번째로 걸린 규칙의 메시지만** 보여준다.

| 순위 | 규칙         | 조건 (정규화 후 기준)       | 처리       | 안내 문구                                 |
| ---- | ------------ | --------------------------- | ---------- | ----------------------------------------- |
| 1    | 🔸 빈 값     | `value === ''`              | 추가 안 함 | 없음 (조용히 무시)                        |
| 2    | 🔸 길이 초과 | `[...value].length > 20`    | 추가 안 함 | `태그는 20자까지 입력할 수 있습니다`      |
| 3    | 🔸 개수 초과 | `tags.length >= 10`         | 추가 안 함 | `태그는 최대 10개까지 추가할 수 있습니다` |
| 4    | ✅ 중복      | 대소문자 무시하고 이미 존재 | 추가 안 함 | `이미 추가된 태그입니다`                  |

- **길이는 `[...value].length`로 센다.** `value.length`는 이모지·일부 한자를 2로 세어 `🏷️`가 들어간 태그가 부당하게 거부된다.
- **중복 판정은 대소문자를 무시한다.** `React`가 있으면 `react`·`REACT`도 중복이다. 저장되는 값은 **먼저 입력된 원문**을 유지한다 (나중 입력으로 덮어쓰지 않는다).

```ts
const isDuplicate = tags.some((t) => t.toLowerCase() === value.toLowerCase());
```

### 5.4 검증 통과 시

1. `tags` 배열 끝에 정규화된 값을 추가한다 (정렬하지 않음)
2. 입력 필드를 비운다
3. 안내 메시지를 지운다
4. 입력 필드에 포커스를 유지한다 (연속 입력 가능)

### 5.5 안내 메시지 표시 방식

`alert()`은 쓰지 않는다 (CLAUDE.md 「에러 처리 패턴」). 입력 필드 아래에 `text-destructive text-xs` 한 줄로 표시한다.

```
┌───────────────────────┐
│ react                   │
└───────────────────────┘
이미 추가된 태그입니다
```

**메시지가 사라지는 시점**: 사용자가 입력값을 바꾸는 순간(`onChange`). 타이머로 자동 제거하지 않는다 — 시간이 지나 사라지면 원인을 놓친다.

> 이는 프로젝트에 **새로 도입되는 패턴**이다. 현재 화면에 에러를 렌더하는 곳은 `NoteList`의 초기 로드 실패뿐이며, CLAUDE.md 「알려진 불일치」 1번이 지적한 "실패가 사용자에게 안 보인다"의 첫 개선 사례가 된다.

## 6. 엣지케이스

### 6.1 한글 IME 조합 중 Enter (가장 중요)

한글 입력 시 **조합을 확정하는 `Enter`와 태그를 추가하는 `Enter`가 겹쳐 태그가 두 번 추가된다.** 한글을 쓰는 이상 반드시 밟는 버그이므로 가드를 넣는다.

```ts
const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>) => {
  if (e.nativeEvent.isComposing) return; // 조합 중이면 무시
  if (e.key !== 'Enter') return;
  e.preventDefault(); // 폼 제출 차단
  addTag(input);
};
```

`e.nativeEvent.isComposing`은 조합이 진행 중인 동안 `true`다. `compositionstart`/`compositionend`를 직접 관리할 필요는 없다.

### 6.2 입력값 엣지케이스

| 입력                          | 결과                                               |
| ----------------------------- | -------------------------------------------------- |
| `""` (빈 문자열)              | 추가 안 함, 안내 없음                              |
| `"   "` (공백만)              | 추가 안 함, 안내 없음, **입력 필드는 비우지 않음** |
| `"  React  "`                 | `React`로 추가                                     |
| `"React  Query"` (연속 공백)  | `React Query`로 추가                               |
| `"React Query"` (내부 공백)   | 허용 — 하나의 태그                                 |
| `"a"` (1글자)                 | 허용                                               |
| `"123"` (숫자만)              | 허용                                               |
| `"C++"` `"#React"` (특수문자) | 허용 — `#`을 제거하지 않고 그대로 저장             |
| `"React, Vue"` (쉼표 포함)    | **하나의 태그**로 저장. 쉼표로 분리하지 않는다     |
| `"🏷️태그"` (이모지)           | 허용, 길이는 `[...value].length`로 계산            |
| 여러 줄 텍스트 붙여넣기       | 개행이 공백으로 치환돼 한 줄 태그가 됨             |
| 1000자 붙여넣기               | 길이 초과로 거부 + 안내                            |
| NFD 한글 (macOS 복사)         | NFC로 정규화 후 기존 태그와 중복 판정              |

### 6.3 개수 제한 엣지케이스

| 상황                                   | 처리                                                                       |
| -------------------------------------- | -------------------------------------------------------------------------- |
| 태그가 10개일 때                       | 입력 필드를 `disabled`하고 placeholder를 `태그는 최대 10개입니다`로 바꾼다 |
| 10개에서 하나 삭제                     | 입력 필드가 즉시 다시 활성화된다                                           |
| `db.json`에 이미 11개 이상 저장돼 있음 | **표시는 모두 한다.** 추가만 막고 기존 데이터를 잘라내지 않는다            |

### 6.4 폼·상태 엣지케이스

| 상황                                         | 처리                                                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 입력 필드에 **미확정 텍스트**를 남긴 채 저장 | 미확정 텍스트는 **버린다.** 자동으로 태그화하지 않는다 — 사용자가 Enter를 누르지 않은 값을 저장하면 의도치 않은 태그가 생긴다 |
| 태그 입력 중 다른 노트 선택                  | 입력 필드·안내 메시지 모두 초기화 (`useEffect` 폼 동기화가 처리)                                                              |
| 취소 버튼                                    | 태그 변경도 함께 되돌아간다 (서버에 안 보냈으므로 자동)                                                                       |
| 저장 실패                                    | `console.error`만 남기고 태그 로컬 state는 **유지** (다시 저장 시도 가능)                                                     |
| 태그만 바꾸고 저장                           | 정상 저장되며 `updatedAt`이 갱신된다 (api 계층이 주입)                                                                        |
| 저장 중(`saving`) 태그 추가·삭제             | 허용한다. 이미 전송된 요청에는 반영되지 않으며 다음 저장에 포함된다                                                           |
| 같은 태그를 지웠다가 다시 추가               | 정상 동작 (배열 끝에 추가되므로 순서만 바뀜)                                                                                  |

### 6.5 표시 엣지케이스

| 상황                  | 처리                                                   |
| --------------------- | ------------------------------------------------------ |
| 태그가 0개            | 칩 영역을 비우고 입력 필드만 노출 (빈 상태 문구 없음)  |
| 20자짜리 태그 여러 개 | 칩 영역이 `flex-wrap`으로 줄바꿈된다. 가로 스크롤 금지 |
| 긴 태그 하나          | 칩이 잘리지 않고 전체가 보인다 (`truncate` 사용 안 함) |

## 7. 계층별 변경 사항

기존 단방향 3계층 흐름을 그대로 따른다.

| 계층   | 파일                            | 변경                                                      |
| ------ | ------------------------------- | --------------------------------------------------------- |
| 타입   | `src/types/note.ts`             | `tags: string[]` 추가, 기존 주석 제거                     |
| 데이터 | `db.json`                       | 기존 노트 3개에 `"tags": []` 추가                         |
| API    | `src/api/notes.ts`              | 변경 없음 — 입력 타입이 `Omit<Note, ...>`라 자동 반영     |
| 상태   | `src/context/NotesContext.tsx`  | `createNote(title, content, tags)` 시그니처에 `tags` 추가 |
| UI     | `src/components/TagInput.tsx`   | **신규** — 칩 목록 + 입력 필드 + 검증                     |
| UI     | `src/components/NoteEditor.tsx` | `tags` 로컬 state, `TagInput` 렌더, 저장 시 전달          |

### 🔸 `TagInput` 컴포넌트를 분리하는 이유

`NoteEditor`가 이미 111줄이고 여기에 칩 렌더·입력·검증·IME 처리가 더해지면 과밀해진다. "파일 하나당 컴포넌트 하나" 컨벤션에도 맞는다.

```ts
interface TagInputProps {
  tags: string[];
  onChange: (tags: string[]) => void;
}
```

`TagInput`은 Context를 소비하지 않고 props만 받는다 (`NoteItem`과 같은 순수 컴포넌트). 검증 로직과 입력 문자열은 `TagInput` 내부 state로 두고, 확정된 `tags` 배열만 `onChange`로 올려보낸다.

## 8. 이번 범위에서 제외

원본 정의서에 없고, 별도 기능으로 다뤄야 하는 것들:

- 태그로 노트 필터링·검색
- 전체 태그 목록 조회 (사이드바 태그 클라우드 등)
- 태그 자동완성 / 기존 태그 추천
- 태그 이름 일괄 변경·병합
- 태그별 색상 지정
- 노트 목록 카드(`NoteItem`)에 태그 표시
- `Backspace`로 마지막 칩 삭제하는 단축키
